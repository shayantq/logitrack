# اصلاحات UI/UX با effort High

تاریخ: ۱۰ نوامبر ۲۰۲۶. این سند شرح پیاده‌سازی و آزمون محلی پیش از انتشار، بر مبنای ممیزی `ui-ux-audit.md` است. نتیجه انتشار با اجرای CI/CD همان commit و بررسی سلامت سرور تأیید می‌شود.

## تغییرات انجام‌شده

- **بارگذاری و ناوبری:** Suspense داخل پوسته پنل قرار گرفت؛ هنگام دریافت کد صفحه، منو و هدر باقی می‌مانند و محتوای اصلی اسکلت دارد. عنوان سند، فوکوس عنوان صفحه و لینک عبور به محتوای اصلی اضافه شدند. باز شدن جزئیات تیکت در همان بخش، قرارداد قبلی حفظ وضعیت را دارد.
- **انتظار، خطا و اطلاعات قبلی:** خطای آمار و آخرین سفارش‌ها دیگر اسکلت بی‌پایان یا پیام نتیجه خالی تولید نمی‌کند. خانه، مرکز اقدام و سفارش‌ها در خطای تازه‌سازی، داده قبلی را همراه آخرین دریافت موفق و امکان تلاش دوباره نمایش می‌دهند. خطای ۴۰۳ داده قبلی را پنهان می‌کند.
- **ساختار خانه:** مرکز اقدام محل اصلی مسائل جاری است؛ سه خلاصه تکراری از BusinessHome حذف شدند. عملکرد مالی با عنوان بازه ۳۰روزه مشخص است. نمای کلی به‌طور پیش‌فرض بسته است؛ ترجیح قبلی کاربر حفظ می‌شود. ثبت سفارش و دریافت کالا از سربرگ خانه قابل دسترسی‌اند.
- **فرم سفارش:** بستن فرم تغییرکرده با انصراف، ضربدر، Escape یا کلیک بیرون، تأیید می‌خواهد. هنگام ارسال، ورودی‌ها و بستن فرم متوقف می‌شوند. خروج/بارگذاری مجدد صفحه اخطار استاندارد مرورگر دارد. Back/Forward داخلی پیش‌نویس را در حافظه همین تب بازیابی می‌کند؛ اطلاعات مشتری در localStorage یا sessionStorage نوشته نمی‌شود. ذخیره موفق یا کنارگذاشتن صریح، پیش‌نویس را پاک می‌کند. بستن کامل تب، حافظه پیش‌نویس را از بین می‌برد.
- **اعتبارسنجی:** خطاهای سفارش کنار فیلد و در خلاصه ماندگار نمایش داده می‌شوند؛ خلاصه به فیلد مربوط فوکوس می‌دهد. مسیر فیلدهای پاسخ ۴۲۲ حفظ می‌شود. خطاهای عمومی نیز تا تلاش بعدی قابل مشاهده‌اند. اعتبارسنجی و قواعد تجاری سمت سرور برقرارند.
- **صفحه‌بندی:** مسیر جدید `GET /orders/page`، اقلام و تعداد کل همان فیلترها را برمی‌گرداند. مسیر قبلی فهرست برای مصرف‌کنندگان دیگر حفظ شده است. فیلتر و اعتبارسنجی مشترک‌اند و از سرویس موجود سفارش استفاده می‌شود. مجوز مدیر ناوگان و پنهان‌سازی مبالغ برای مسیر جدید آزموده شده‌اند. مایگریشن لازم نیست.
- **انتخاب گروهی:** اندازه صفحه ۲۵، ۵۰، ۱۰۰ یا ۲۰۰؛ انتخاب سرصفحه فقط ردیف‌های همین صفحه را انتخاب می‌کند و حالت انتخاب بخشی دارد. تغییر صفحه/فیلتر/مرتب‌سازی انتخاب را پاک می‌کند. دریافت صفحه تازه و داده قدیمی پس از خطا، عملیات گروهی را غیرفعال می‌کنند. ردیف‌های خارج‌شده با تازه‌سازی از انتخاب حذف می‌شوند.
- **فیلترها:** متن، انتخاب‌ها و میان‌بر روز تحویل همگی پیش‌نویس‌اند و با «اعمال فیلترها» اعمال می‌شوند. تغییرات اعمال‌نشده مشخص‌اند. حذف چیپ، پاک‌کردن و اعمال نمای ذخیره‌شده اقدام صریح‌اند. فیلتر، صفحه، اندازه و مرتب‌سازی در URL نگهداری می‌شوند و Back کار می‌کند. نتیجه بدون فیلتر و نتیجه صفرِ فیلترشده، پیام و اقدام متفاوت دارند.
- **کیبورد و اجزای مشترک:** شناسه مستقل هر کنترل، اتصال label/hint/error، وضعیت busy و پیام انتظار اضافه شدند. Select جست‌وجوشونده فوکوس و active descendant معتبر دارد؛ گزینه غیرفعال انتخاب نمی‌شود و نتیجه خالی انتخاب اشتباه نمی‌سازد. مودال فوکوس را به کنترل بازکننده برمی‌گرداند. کد پیگیری دکمه واقعی است و تخصیص خودکار/بعداً از radio بومی استفاده می‌کند.

## بررسی

- build نهایی TypeScript و Vite در Docker موفق بود.
- ۲۵ تست API جستجو و صفحه‌بندی، شامل ترتیب ثابت، چند صفحه، فیلتر، شمارش، سازمان، راننده، نقش محدود و حدود ورودی: موفق.
- ۴۲ تست API خانه نقش‌ها، مرکز اقدام و مدیر ناوگان: موفق.
- ۱۳ سناریوی مرزی Chromium در `tests/ui/high-ux.mjs`: موفق؛ شامل تأخیر کد lazy، فوکوس، فیلتر، اعتبارسنجی بومی و سرور، پیش‌نویس، ۴۵۱ نتیجه، مرز انتخاب ۲۰۰تایی، خطای تازه‌سازی، ۴۰۳، خطای مستقل داشبورد، موبایل و دو تم.
- مجموعه کامل `tests/ui/e2e.mjs` و سناریوهای `high-ux.mjs` در CI روی استک تازه اجرا می‌شوند. نتیجه نهایی، لاگ و تصاویر در Job Summary و artifact همان اجرای GitHub Actions قابل بررسی‌اند؛ موفقیت این مرحله و دیگر مراحل CI شرط استقرار است.

این بررسی روی استک مستقل `pasineh_high` با پورت وب ۸۰۰۳، دیتابیس/volume مستقل و image اختصاصی انجام شده است. آزمایش‌ها به استک اصلی ۸۰۰۱ یا سایت اصلی داده‌ای ننوشته‌اند. شبیه‌سازی خطاهای UX فقط در مرورگر آزمایشی بوده است.

فرانت‌اند جدید به مسیر صفحه‌بندی جدید نیاز دارد؛ انتشار باید شامل فرانت‌اند و بک‌اند با هم باشد. ساخت معمول Docker پروژه هر دو را در یک image قرار می‌دهد.

اسکن CI پیش از انتشار، دو آسیب‌پذیری zlib در image پایه گزارش کرد. Dockerfile برای دریافت اصلاح رسمی Debian به‌روز شد؛ نسخه اصلاح‌شده در trixie برابر `1:1.3.dfsg+really1.3.1-1+deb13u1` است. اسکن حذف یا مستثنا نشده است. مرجع: [ردیاب رسمی امنیت Debian](https://security-tracker.debian.org/tracker/source-package/zlib).

اسکن محلی با پایگاه تازه‌تر، آسیب‌پذیری apt را هم گزارش کرد؛ apt و کتابخانه وابسته آن نیز با بسته رسمی Debian اصلاح می‌شوند. مرجع: [CVE-2026-109518](https://security-tracker.debian.org/tracker/CVE-2026-109518).

## مرحله Medium

کنتراست رنگ‌ها در هر دو تم، سلسله‌مراتب تایپوگرافی، فاصله‌ها و تراکم کارت/جدول، اسکلت اختصاصی هر نوع صفحه، ابعاد کنترل‌های لمسی و پولیش حرکت/کاهش حرکت در این مرحله تغییر نکردند. اندازه‌گیری کاربردپذیری با کاربران و اعلام انطباق کامل WCAG نیز انجام نشده است.
